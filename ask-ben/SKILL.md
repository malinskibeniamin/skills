# Ask Ben
frontend/React/TypeScript/Go skills repo; installable plugin surfaces.
Two everyday entry points: `/work <outcome + endpoint>` for authoring/delivery;
`/review <branch or PR>` for read-only assessment. Authoring selects evidence, visuals,
PR presentation and delivery helpers; users do not sequence `/work` -> `/go`.
Other commands are specialists or compatible presets. For open decisions use `/grilling`;
for hard bugs `/diagnosing-bugs`; huge, foggy work `/wayfinder` -> `/to-spec` -> `/to-tickets` (parallel: `/implement-spec`); retro `/retro`.
Parallel work still requires explicit delegation. [Phases](PHASE-BOUNDARIES.md).
After a bug fix, recommend `/retro` to ask what would have prevented it; recommend `/improve-codebase-architecture` for a missing seam. Both are human-invoked, not automatic handoffs.
Before recommending/skipping, read canonical `SKILL.md`; catalogs only orient.
