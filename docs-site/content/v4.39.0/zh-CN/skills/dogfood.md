**重要可运行切片**会改变真实入口或公共接缝可触达的行为。
每个切片和最终完整 PR 都要 dogfood。测试不是 dogfood。

## 清点

1. 用
   `BASE=$(PR_BASE_REF="${DOGFOOD_BASE_REF:-}" "${CLAUDE_PLUGIN_ROOT:-.}/scripts/resolve-pr-base.sh")`
   确定比较基线。
2. 从合并基点检查完整 PR，包括已提交、已暂存、未暂存和未跟踪工作。
3. 将变更的行为映射到其真实入口。技能包含引用指南、资产和
   脚本；钩子通过真实事件运行。独立文档、测试和评估不要求
   体验覆盖。

本地覆盖本轮变更。创建 PR 或发布前，覆盖分支中全部可运行行为。

## 循环

在当前实现上运行**使用 -> 滥用 -> 修复 -> 重放**。

### 使用

通过实际实现完成每条预期路径。直接检查可见输出、
状态转换、副作用、控制台、网络和日志，不从代码推断。

使用形状和基数接近生产的代表性真实规模数据。比较
预期与观察到的数量、顺序、耗时、状态和副作用；运行足够长时间以
暴露累积问题。

对于缺陷，先在未修复行为上重放报告者的精确步骤。无法复现时，
停止诊断，请求缺失环境或证据。

### 滥用

应用每个相关视角，并至少尝试一种可信破坏方式：

- 粗心：空、无效、超大、重复或乱序输入。
- 急躁：重复、双击提交、重载、离开、取消或中断。
- 倒霉：陈旧或缺失数据、依赖缓慢或失败、部分完成。
- 真实数据：稀疏字段、重复 ID、混合版本或租户、长文本、Unicode、
  时区边界、真实基数。
- 性能：对照基线或预算测量响应时间、网络、渲染、CPU 和内存。

优先选择可信用户行为。直接观察失败和恢复。

### 修复

观察到的缺陷会使检查点失败。可自动化时，先添加 RED 公共契约测试，
再通过 `/tdd` 修复并运行聚焦检查。任何行为编辑都会使旧证据失效。

### 重放

从真实入口重启，重复正常使用和全部破坏尝试。修复缺陷时，
重放完全相同的原始复现并检查相邻行为。PASS 只绑定
当前可运行状态。

## 入口

| 变更 | 操作 |
|---|---|
| Web/UI | 运行、导航、操作、重载并检查控制台/网络 |
| CLI/TUI | 调用真实、无效和中断流程 |
| API/worker | 发送真实请求/事件，检查响应与副作用 |
| 库 | 从最小消费者调用公共 API |
| 钩子/自动化 | 用代表性夹具触发真实事件 |
| 技能/智能体 | 在全新真实任务上使用并检查行为 |
| 演示/原型 | 操作到问题获得可观察证据 |

优先使用项目原生工具。新智能体需要明确授权委派。

如果存在项目本地的 `verify-*` 技能，请使用其中的 doctor、drive、evidence 和 cleanup。
验证器漂移交由 `/maintain-verification-skill` 处理；反复缺失的路径在得到证据后交由
`/create-verification-skill` 处理。

## 回执

将入口、操作和观察绑定到当前实现。
报告 `Verdict: PASS | FAIL | BLOCKED`，然后包含：

- **Entrypoint：** 精确命令、URL、事件或消费者。
- **Actions：** 正常路径和破坏尝试。
- **Observations：** 数据、输出、状态、副作用、控制台/网络/日志和耗时。
- **Repairs：** 缺陷、RED 测试、修复和重放结果。
- **Limits：** 未尝试行为及原因。

PASS 要求每项变更行为都有直接证据。FAIL 表示仍有已观察缺陷。
BLOCKED 指明缺失访问、环境、硬件或安全条件。
