这些原则经受住了每一次技术栈迁移（UI 工具包、路由器、数据层、表单库和状态库都被淘汰了，而这些原则始终保留）。当不变量与特定技术栈的规则冲突时，以不变量为准；技术栈的具体机制记录在 `/stack-registry` 中。

## 放大效应原则
每一个被容忍的反模式、逃生舱或抑制措施，都会成为下一次 LLM 会话模仿和传播的训练样本。应从源头修复；只有在同一行说明理由时才能抑制；绝不允许“仅此一次”。

## 如实渲染
1. **渲染绝不能造假。** 不使用虚假默认值，不以有损的美化格式展示无法解码的数据，不隐藏有效的零值（显示数值时使用 `value == null`，绝不依赖真假值判断）。降级状态应列出可能的原因，逐字引用上报的原因，并提供重试选项。
2. **在便于理解的标签旁展示机器真实值** -- 在运维人员需要时显示 ID/原始值；展示字符串应派生生成，绝不将机器键直接作为标签显示。
3. **未就绪前不显示任何内容** -- 未就绪的功能应隐藏，而不是提前展示；加载状态应预留布局空间（避免 CLS）。
4. **每个界面都应处理完整的状态矩阵**：加载中 / 空状态 / 错误 / 无权限 / 已禁用 / 卡住 -- 而不只是正常路径。

## 状态放置
5. **URL = 可共享状态**（标签页、筛选条件、排序方式、页码）；**本地/会话存储 = 个人偏好**（显示密度、折叠面板）；**服务端缓存 = 服务端数据**；组件状态仅用于随组件销毁的内容。绝不能混用。
6. **同一分区内的导航替换历史记录；进入分区时新增历史记录** -- “返回”应退出该分区，而不是重放访问过的每个标签页。
7. **反复出现的异步元缺陷**：状态通过异步解析，却被过早读取或作用域过宽 -- 按完整作用域（环境/组织/用户）设置缓存键；导航前等待清理完成；中止陈旧响应或采用最后一次写入生效策略；提供程序解析完成前不要读取功能开关/配置的默认值。

## 与设计系统的关系
8. **优先使用令牌，而非临时值** -- 颜色、间距和字体都应取自标度；将设计师给出的一次性数值舍入到最接近的档位；存在令牌时绝不硬编码十六进制颜色值或像素值。
9. **从源头修复共享组件** -- 绝不分叉、内联重设样式或使用深层选择器修改共享组件；只有明确指出缺陷并创建上游修复工单时，才可接受分叉。
10. **构建前先搜索系统** -- 你需要的组件很可能已经存在；当使用方反复误用某个 API 时，应修复 API，而不是修复使用方。

## 交互
11. **按钮执行操作，链接负责导航** -- 任何会更改 URL 的元素都应是真正的链接（支持按住 cmd 点击）；操作使用按钮；禁用的控件应提供可感知的原因。
12. **破坏性流程默认拒绝执行** -- 只有在刚刚成功完成零引用检查后，确认操作才能启用；所有关闭路径（X/ESC/Enter/返回）都必须尊重进行中的操作和未保存状态。
13. **默认克制地使用动效** -- 仅在动画有助于说明状态变化时使用；遵循 `prefers-reduced-motion`；删除妨碍可用性的动画。

## 流程
14. **尽可能少地在边界接缝处使用模拟**；仅模拟异常路径；测试工厂应构造真实类型（直接赋值，绝不深度合并）。
15. **测试应证明用户能够触发的副作用** -- 删除仅验证渲染的测试；等待触发原因，而不是等待固定时长。
16. **迁移结束时应通过机械化规则冻结旧模式**；移除功能开关是其完成定义的一部分。
17. **严格控制范围**：PR 应保持单一目的；迁移只做迁移；延期事项应附带工单链接；依赖项升级与注册表同步应分别发布。
18. **命名应详尽且精确指向实体** -- 路由/文件/标签中不使用缩写；布尔值命名应读起来像谓词；精确性同时也是抵御 LLM 幻觉的手段。
19. **领域事实应来自领域负责人** -- 继承链、单位（GiB 与 GB）、命名标准、SLA 都应注明来源并引用，绝不能在 UI 中主观假定。
20. **前端审查应包含安全检查** -- Git 历史中不得出现密钥；日志/回放/失败转储应脱敏；鉴权失败时默认拒绝访问；读取操作绝不能产生变更；审计 URL 持久化可能泄露的信息。
