Move issues through a small role state machine. For configured external pull requests, a
PR is an issue with attached code; resolve bare numbers through the tracker.
Use the domain glossary and relevant ADRs. Read current external docs with
`/read-the-damn-docs`; use `/plan-arbiter` for competing plans and `/visual-plan` for large epics.

## Comment invariant

Start every posted triage comment with:

```markdown
> *This was generated by AI during triage.*
```

## Tracker and roles

Detect the tracker from repository instructions and remotes:

- GitHub: use `gh` via [tracker-github.md](https://github.com/malinskibeniamin/skills/blob/v4.39.0/triage/tracker-github.md).
- Jira: use `acli` via [tracker-jira.md](https://github.com/malinskibeniamin/skills/blob/v4.39.0/triage/tracker-jira.md).
- GitHub and Jira both plausible: ask which owns the item.

Each triaged item has exactly one category (`bug` or `enhancement`) and one state:
`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, or `wontfix`.
Map these canonical roles to existing tracker labels/statuses. Conflicting states require a
decision before mutation.

## Show attention queue

Query oldest first:

1. Unlabeled or no-status items.
2. `needs-triage` items.
3. `needs-info` items with new reporter activity.

Include configured external items, marking every line `[PR]` or `[issue]`; collaborators'
active PRs are not discovery work. An explicitly named PR remains in scope. Show counts, then let
the maintainer choose.

## Triage one item

1. **Gather.** Read body, comments, labels/status, reporter, dates, prior triage notes, and a
   PR diff when present. Do not repeat answered questions.
2. **Explore.** Run a redundancy search by domain concept for an existing implementation.
   Check `.out-of-scope/` for a prior rejection.
3. **Recommend.** Present category, state, reasoning, and codebase evidence; wait for direction.
4. **Verify the claim.** Reproduce a bug or check out and test a PR. Report confirmed, failed, or
   insufficient evidence. For root-cause and RED/GREEN planning, follow
   [REFERENCE.md#tdd-fix-plan-mode](https://github.com/malinskibeniamin/skills/blob/v4.39.0/triage/REFERENCE.md#tdd-fix-plan-mode).
5. **Grill if needed.** Use `/grilling` for unresolved judgment or domain language.
6. **Apply.** Use [AGENT-BRIEF.md](https://github.com/malinskibeniamin/skills/blob/v4.39.0/triage/AGENT-BRIEF.md) for ready states and
   [REFERENCE.md](https://github.com/malinskibeniamin/skills/blob/v4.39.0/triage/REFERENCE.md) for `needs-info` notes. For `wontfix`:
   - already implemented: link it and close; do not add rejection history.
   - Bug: explain and close.
   - Enhancement: record it with [OUT-OF-SCOPE.md](https://github.com/malinskibeniamin/skills/blob/v4.39.0/triage/OUT-OF-SCOPE.md), link, and close.
   Apply `needs-triage` without a comment unless partial work needs recording.

## Overrides and resume

For an explicit state override, state the mutations and act; skip grilling. Ask whether to
write an agent brief only when moving to `ready-for-agent` without one.
On resume, read prior notes and new replies, then present the updated state without re-asking.

Full templates and state transitions: [REFERENCE.md](https://github.com/malinskibeniamin/skills/blob/v4.39.0/triage/REFERENCE.md).
