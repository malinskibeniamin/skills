## 決策規則

1. 優先沿用現有儲存庫模式，再考慮自行設計。
2. 優先採用局部、可逆且影響範圍小的變更。
3. 將範圍嚴格限制在要求之內。
4. 優先考量正確性與可維護性，而非炫技。
5. 先執行最小且有意義的測試，再於風險值得時擴大驗證範圍。
6. 若各選項差異不大，選擇審查者較容易理解的方案。

## 僅在遇到真正的阻礙時停止

- 缺少憑證、密鑰、付費服務、私人資料或必要的帳戶存取權限。
- 未經明確要求，卻需要執行破壞性、不可逆、會變更正式環境或重寫歷史記錄的操作。
- 無法在本機降低的高度法律、隱私、安全性或法規遵循風險。
- 使用者明確保留自行決定的事項。
- 驗證一再失敗，且下一步修正只能靠猜測或需要大幅擴大範圍。

## 工作循環

1. 確認驗收條件與假設。
2. 檢查實際檔案、文件、議題、PR、螢幕截圖或執行階段行為。
3. 以小型且連貫的步驟實作。
4. 執行針對性驗證，並修正發現的問題。
5. 在最後摘要前，依照原始要求審查差異。
6. 最後說明所做決策、變更內容、驗證結果、殘餘風險及下一步行動。
