**精靈**是一個 Bash 指令碼，會逐步引導人工完成手動程序；這類程序不但手動操作繁瑣，每次都要重新向 AI 說明也很麻煩。它會開啟每個 URL、明確說明要點選和複製的內容、擷取值並寫入正確位置（`.env`、GitHub 密鑰），在每個階段要求確認，並顯示還剩多少個階段。它可以設定第三方服務、執行一次性遷移，或將專案從一種狀態切換至另一種狀態。

令人愉悅的使用者體驗已由 [template.sh](https://github.com/malinskibeniamin/skills/blob/v4.38.0/wizard/template.sh) 完整處理，包括逐階段進度、確認關卡、跨平台開啟 URL（包含 WSL）、隱藏密鑰輸入、具冪等性的 `.env` 更新插入、寫入 `gh secret`/`gh variable`，以及結束摘要。**你的工作只有界定程序範圍並撰寫各階段。** `STAGES` 標記上方的程式庫在每個精靈中都完全相同；一致性正是重點，因此絕對不要手動編輯它。

精靈預設是暫時性的：為單次執行而建立，儲存至暫存路徑或 `scripts/` 路徑，工作完成後便刪除。只有當使用者希望建立應保留在儲存庫中的可重複設定流程時，才提交精靈。

## 流程

### 1. 界定程序範圍

釐清人工必須執行的每個手動步驟，以及過程中需要擷取的每個值。先閱讀儲存庫，不要在毫無背景資訊的情況下提問。若為第三方設定流程，請先執行 `/read-the-damn-docs`，再指出儀表板點選項目、URL、權限範圍、密鑰或 CLI 命令：

- 設定時：檢查 `.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架設定，以及 `.github/workflows/*`（每個 `secrets.*` / `vars.*` 參照都是精靈必須產生的值）。
- 遷移或轉換時：釐清目前狀態、目標狀態，以及兩者之間不可逆的操作。

接著向使用者顯示依序排列的階段清單，以及每個階段會產生的值，並請其確認；使用者可能會新增、移除或重新排序階段。

**完成條件：**每個階段皆已依序命名，且對於每個擷取的值，你都知道：(a) 人工要從何處取得、(b) 要寫入何處（`.env`、GitHub 密鑰、兩者皆是，或皆非；部分階段僅執行操作），以及 (c) 該值是密鑰（隱藏輸入）還是公開值。

### 2. 規劃每個階段的操作路徑

針對每個階段，寫出人工應遵循的精確路徑：要開啟哪個 URL、要在其中執行什麼操作、值會顯示在哪裡，以及該值要填入哪個變數。例如：「儀表板 -> 開發人員 -> API 金鑰 -> 顯示測試金鑰 -> 複製」。若你其實不知道目前的使用者介面或確切命令，請坦白說明並詢問使用者或查閱文件；絕對不要虛構可能不存在的步驟。

**完成條件：**每個階段都有具體指示，即使是陌生人也能照著完成。

### 3. 撰寫精靈

將 `template.sh` 複製到目標路徑。依照相依性順序，以每個步驟一個 `stage` 取代範例階段。使用程式庫輔助函式：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`，並將 `TOTAL_STAGES` 設為所撰寫的階段數。

維持範本所訂的標準：詢問值之前先開啟 URL、任何密鑰皆使用 `ask_secret`、每個需要保存的值皆使用 `write_env`、只有 CI 實際需要的值才使用 `set_secret`，並在任何不可逆操作前使用 `confirm`。每個 `stage` 都會清除畫面，因此只顯示目前步驟；請讓每個階段專注於單一任務，以免人工所需的內容捲動至畫面之外。不要更動標記上方的程式庫。

### 4. 驗證並交付

- 執行 `bash -n <script>`；若有可用的 `shellcheck`，也請執行。
- 執行 `chmod +x <script>`。
- 不要自行從頭到尾執行；它會開啟瀏覽器並等待人工輸入而停住。請改為靜態追蹤：步驟 1 的每個值皆已擷取並寫入步驟 1 指定的位置，且每個 `set_secret` 名稱都與 CI 中的 `secrets.*` 參照完全相符。
- 告訴使用者如何執行精靈。若這是可重複使用的設定流程，請提交精靈並從 README 連結至該精靈，讓下一位使用者直接執行指令碼，而不必詢問 AI。
