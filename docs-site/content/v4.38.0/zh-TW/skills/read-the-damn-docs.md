閱讀 `references/builder-upstream.md` 以取得完整的文件優先觸發條件清單。

如果權威文件可以回答問題，就不要猜測。這是快速查核官方資訊的途徑，通常不需要建立研究產出。當使用者想要可長期保存且附有引用的報告，或多來源綜整時，請委派給內建的深度研究技能，然後將研究結果儲存為 Markdown 檔案，放在儲存庫現有的此類筆記位置（或合理的路徑，並說明儲存位置）。

## 必要工作流程

1. 識別確切介面：套件、版本、端點、CLI、設定、本機輔助工具、結構描述或產品行為。
2. 當本機儲存庫的文件、規格、ADR 或產生的型別已定義合約時，優先閱讀這些內容。
3. 對於第三方或快速變動的行為，搜尋最新的官方文件，並開啟相關的 API 參考資料、遷移指南、變更記錄、版本資訊、SDK 原始碼或型別定義。
4. 僅擷取所需事實：選項名稱、匯入、生命週期規則、預設值、重大變更、限制、權限、範例。
5. 將文件內容套用至程式碼。不要照搬與儲存庫模式衝突的範例。
6. 當文件中的事實至關重要時，請在研究筆記或最終答案中引用來源。

## 強烈觸發條件

- 使用者提到最新、目前、官方、支援、最佳實務、今天、現在，或要求查詢。
- 新增、升級、設定或匯入套件、SDK、模型、供應商、外掛程式或 CLI。
- 錯誤提及已棄用、未知選項、缺少匯出、無效設定、不支援的欄位或版本不相容。
- 難以回復的高成本決策：公開的線路格式、資料庫結構描述、永久性 ID、事件名稱、客戶可見的行為、外部自動化。
- 涉及驗證、OAuth 範圍、密鑰、Webhook、個人識別資訊、加密、保留政策、遷移、重試、速率限制、配額、計費或部署行為。
