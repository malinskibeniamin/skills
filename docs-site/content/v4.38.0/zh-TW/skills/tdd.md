TDD 保護有意義的行為；它不是每個異動檔案都必須承擔的成本。

針對錯誤、迴歸，以及新增或變更的契約，使用 RED -> GREEN -> REFACTOR：
領域規則、分支、狀態轉換、解析、驗證、非同步副作用，以及一旦失敗便會造成實質影響的整合行為。
型別、重新匯出、宣告式串接、靜態文案／樣式，以及不改變行為的刪除，
可能只需要執行既有的聚焦驗證。

涵蓋率可以揭露疑似的測試盲點。它絕不是目標，也不是憑空新增測試的理由。

## 測試接縫與反模式

- **接縫**：在公開邊界進行測試。撰寫測試前，先記下接縫；若問題或既有慣例未能明確指出接縫，請向使用者確認事先議定的接縫。不得針對未經確認的內部實作進行測試。
- **恆真式測試**：不要用與程式碼相同的方式重新計算預期值；請使用獨立的事實來源：已知正確的常值、完整推導的範例、測試資料、規格或觀察到的行為。
- **水平切片**：不要先寫完所有測試，再撰寫所有實作。批次撰寫的測試是在測試想像中的行為。正確做法是垂直切片——先完成一個 RED->GREEN 測試與實作，再重複進行。

若公開接縫本身並不明確，請使用 `/codebase-design`；不要為了方便測試而憑空建立內部接縫。

## 工作流程

### 0. 契約

- 說明公開介面上可觀察到的行為。遵循專案的領域詞彙表與 ADR。
- 選擇一個最小的測試，確保該行為一旦失效，測試就會失敗。一個測試可以驗證多行程式碼。
- 只有在存在獨立且可信的風險時才新增案例，而不是為每個想像得到的邊界情況都新增案例。
- 當單一不變條件橫跨高基數輸入或可達的狀態序列時，請閱讀
  [屬性式測試](https://github.com/malinskibeniamin/skills/blob/v4.38.0/tdd/PROPERTY-BASED-TESTING.md)。必須具備獨立的判定依據與可重播的失敗案例。
- 對於長時間存續的瀏覽器頁面中的資源生命週期契約，請使用可重複的
  往返操作，並閱讀 [SPA 浸泡測試](https://github.com/malinskibeniamin/skills/blob/v4.38.0/e2e-testing/SOAK-TESTING.md)。全新的
  瀏覽器情境無法揭露多次互動所造成的累積。
- 如果契約是由第三方行為定義，請使用 `/read-the-damn-docs`。
- 當接縫或測試形式不明確時，請閱讀 [tests.md](https://github.com/malinskibeniamin/skills/blob/v4.38.0/tdd/tests.md)。

### 1. RED

- 撰寫一個行為測試，並確認它會基於預期原因而失敗。
- 優先使用真實的公開介面；只有無法在本機執行的外部邊界才使用模擬。

### 2. GREEN

- 撰寫能通過測試、最小且顯而易見的實作。
- 優先刪除或重用；接著優先採用語言、平台或已安裝的相依套件，而不是自行打造機制。
- 遵循相關 `exemplars/` 檔案的清晰度與慣例，而不是其規模。

### 3. REFACTOR

- 只有在語意會變得更清楚，或能消除實際重複時，才改善命名與結構。
- 維持綠燈。絕不可只為了通過測試而弱化行為斷言。
- 標記執行時間超過 500 毫秒的單元測試，以及超過 2 秒的整合測試；優先使用批次輸入，而不是逐鍵模擬。
- 對實質且可執行的行為執行 `/dogfood`；觀察到的缺陷將成為下一個 RED。

### 4. 重複

只有在存在另一項必要契約或獨立且可信的風險時才重複進行。

進行中的工作請監控 `vitest --watch`。當異動會建立非同步工作時，請使用條件式等待與
`--detectAsyncLeaks`。

## 測試分類

| 後綴 | 用途 | DOM？ |
|--------|---------|------|
| `.test.ts` | 單元——純邏輯 | 否 |
| `.test.tsx` / `.integration.tsx` | 整合——算繪元件 | 是 |
| `e2e/*.spec.ts` | E2E——Playwright 瀏覽器 | 瀏覽器 |

## 視覺迴歸測試

當路由新增尚未涵蓋的客戶可見行為，且專案使用
`@vitest/browser` 時，請新增最小且實用的 `*.browser.test.tsx`。若是
版面配置、重新導向或純宣告式路由，則略過。

## 完成條件

- 相關測試通過且沒有警告。
- 非同步異動沒有洩漏的工作或以持續時間為基礎的等待。
- 測試能承受內部重構，因為它們驗證的是行為，而非實作。
- 不存在僅為提高涵蓋率而新增的多餘案例。

如需條件式等待、選擇器、Portal、模擬、診斷，以及針對性的韌性範例，請參閱
[REFERENCE.md](https://github.com/malinskibeniamin/skills/blob/v4.38.0/tdd/REFERENCE.md)。
