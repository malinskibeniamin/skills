這些原則歷經每次技術堆疊遷移後依然適用（UI 套件、路由器、資料層、表單與狀態函式庫都曾遭淘汰，唯獨這些原則屹立不搖）。當不變原則與特定技術堆疊的規則衝突時，以不變原則為準；技術堆疊的運作細節則記載於 `/stack-registry`。

## 放大效應原則
每個被容忍的反模式、逃生通道或抑制措施，都會成為下一個 LLM 工作階段模仿並散播的訓練範例。從源頭修正；只有在同一行註明理由時才能抑制；絕不容許「只此一次」。

## 如實呈現
1. **絕不在畫面呈現上造假。** 不使用虛假預設值、不以失真的美化格式顯示無法解碼的資料，也不隱藏有效的零值（顯示數值時使用 `value == null`，絕不使用真值判斷）。降級狀態應列出可能原因、逐字引用回報的原因，並提供重試選項。
2. **在易懂標籤旁呈現機器原始資料** -- 在操作人員需要時顯示 ID／原始值；顯示字串應由資料衍生，絕不直接將機器鍵值當成標籤顯示。
3. **尚未就緒前不顯示任何內容** -- 未就緒的功能應隱藏，而非預告；載入時應預留版面空間（避免 CLS）。
4. **每個介面都應處理完整的狀態矩陣**：載入中／無資料／錯誤／無權限／已停用／卡住 -- 而非只處理正常流程。

## 狀態配置
5. **URL = 可分享的狀態**（分頁、篩選條件、排序、頁碼）；**本機／工作階段儲存空間 = 個人偏好設定**（資訊密度、收合面板）；**伺服器快取 = 伺服器資料**；元件狀態只用於隨元件一同消失的內容。絕不混用。
6. **區段內導覽取代瀏覽紀錄；進入區段時新增紀錄** -- 「返回」應離開該區段，而不是重播每次分頁切換。
7. **反覆出現的非同步元問題**：狀態以非同步方式解析，卻過早讀取或套用範圍過廣 -- 快取鍵必須涵蓋其完整作用域（環境／組織／使用者），導覽前等待清理完成，中止過時的回應或採取最後寫入者勝出策略，且不要在提供者解析完成前讀取旗標／設定的預設值。

## 與設計系統的關係
8. **優先使用權杖，避免臨時自訂值** -- 色彩、間距與字型排印全都取自既定尺度；將設計師的一次性數值取整到最接近的級距；已有權杖時，絕不寫死十六進位色碼／像素值。
9. **從源頭修正共用元件** -- 絕不分支複製、就地重新設定樣式，或使用深層選擇器修改共用元件；只有在指出具名缺陷，並建立向上游修正的工單時，才可接受分支版本。
10. **建置前先搜尋系統** -- 你需要的元件很可能已經存在；當使用端反覆誤用某個 API 時，應修正 API，而不是修正每個使用端。

## 互動
11. **按鈕執行動作，連結負責導覽** -- 任何會變更 URL 的項目都必須是真正的連結（可使用 cmd-click）；動作使用按鈕；停用的控制項必須提供可感知的原因。
12. **破壞性流程應採失敗時關閉策略** -- 只有在重新檢查並成功確認參照數量為零後，才能啟用確認操作；所有關閉方式（X／ESC／Enter／返回）都必須正確處理進行中的操作與未儲存狀態。
13. **預設克制使用動態效果** -- 只有在動畫能釐清狀態變更時才使用；遵循 `prefers-reduced-motion`；移除妨礙可用性的動畫。

## 流程
14. **在邊界接縫處進行模擬，且越少越好**；只模擬異常流程；測試工廠應建構真實型別（直接指派，絕不深層合併）。
15. **測試應證明使用者可觸發的副作用** -- 刪除只驗證轉譯結果的測試；等待成因發生，絕不等待固定時長。
16. **遷移工作須以機械式凍結舊模式作結**；移除功能旗標是其完成定義的一部分。
17. **嚴守範圍**：PR 應用途單一；遷移只處理遷移；延後項目必須附上工單連結；相依套件升級與登錄檔同步應分開發布。
18. **採用詳細且精確對應實體的命名** -- 路由／檔案／標籤中不使用縮寫；布林值名稱應讀起來像述詞；精確命名同時也是防止 LLM 產生幻覺的措施。
19. **領域事實應取自領域負責人** -- 繼承鏈、單位（GiB 與 GB）、命名標準、SLA 都必須有來源並加以引用，絕不可在 UI 中自行假設。
20. **前端審查應包含安全性檢查** -- Git 歷史紀錄中不得出現密鑰，應遮蔽記錄檔／重播資料／失敗傾印中的敏感資訊，授權失敗時採關閉策略，讀取操作絕不產生異動，並稽核持久化於 URL 的資料會洩漏哪些資訊。
