如果权威文档能够回答问题，就不要猜测。这是快速核查官方事实的路径，通常无需创建研究产物。当用户需要可长期保存且带引用的报告或多来源综合分析时，委派给内置的深度研究技能，然后将研究结果保存为 Markdown 文件，放在仓库中已有的此类笔记存放位置（或合理的路径，并说明保存位置）。

## 必需工作流程

1. 明确具体对象：包、版本、端点、CLI、配置、本地辅助工具、模式或产品行为。
2. 如果本地仓库文档、规范、ADR 或生成的类型定义了契约，请先阅读它们。
3. 对于第三方或快速变化的行为，搜索当前官方文档，并打开相关的 API 参考、迁移指南、更新日志、发行说明、SDK 源码或类型定义。
4. 仅提取所需事实：选项名称、导入方式、生命周期规则、默认值、破坏性变更、限制、权限和示例。
5. 将文档内容应用到代码中。不要照搬与仓库模式冲突的示例。
6. 当文档中的事实很重要时，在研究笔记或最终答复中引用来源。

## 强触发条件

- 用户提到最新、当前、官方、受支持、最佳实践、今天、现在或要求查询。
- 添加、升级、配置或导入包、SDK、模型、提供商、插件或 CLI。
- 错误中提到弃用、未知选项、缺少导出、配置无效、字段不受支持或版本不匹配。
- 决策的回退成本很高：公共传输格式、数据库模式、持久化 ID、事件名称、客户可见行为或外部自动化。
- 涉及身份验证、OAuth 权限范围、密钥、Webhook、个人身份信息、加密、保留策略、迁移、重试、速率限制、配额、计费或部署行为。
