撰寫讀者能夠理解、驗證與使用的文件。

## 載入指引 [#load-guidance]

1. 先閱讀[工具組相容性規則](https://github.com/malinskibeniamin/skills/blob/main/shared/FLIGHTRULES-COMPATIBILITY.md)。
2. 完整閱讀[固定版本的上游 docs 技能](https://github.com/malinskibeniamin/skills/blob/main/vendor/flightrules/skills/docs/SKILL.md)。
3. 上游指引與相容性規則不同時，套用相容性規則。閱讀
   [溝通規則](https://github.com/malinskibeniamin/skills/blob/main/shared/communication.md)，了解首次閱讀的結構與作者意圖。

## 撰寫或審查 [#write-or-review]

1. 確認讀者、要求的文件、來源證據與終點。沿用
   既有路徑、範本與術語。僅要求審查時，提出發現，不進行編輯。
2. 先說明讀者需要的成果。區分目前行為、提案、估算
   與未知事項。為數字主張提供來源，並為所述結果提供可重現的指令。
3. 保留作者意圖，以及原樣的程式碼、指令、識別字、引用的錯誤與事實。
   簡化文字，但不刪除重要限定條件。使用儲存庫支援的格式，為有意義的結構繪製圖表；
   將提議的路徑標示為提案。
4. 對照來源驗證每項修改後的主張。執行儲存庫的文件與連結檢查；
   若沒有檢查工具，使用工具檢查修改後的內部檔案連結與相關交叉參照。
   支援時驗證片段錨點。絕不宣稱未執行的指令已成功。
5. 回報結果、實際觀察到的驗證情況與尚未解決的證據缺口。遵守
   要求的終點；此技能不授權無關的發布或設定操作。
