向對主題一無所知的人解釋該主題。以請求內容作為主題；
若明確叫用，則以 `$ARGUMENTS` 為準。

## 約定

1. 先以證據為基礎，再簡化說明。針對模組、取捨或事件，檢視相關原始
   資料。對於外部事實，優先採用最新的第一手
   來源。絕不可為了讓敘事更流暢而虛構因果步驟。分別標示事實與推論，
   包括重大的不確定性。
2. 選擇一個能保留重要事實的心智模型。盡可能移除術語；
   若術語無法避免，請在圖片旁以日常用語加以定義。
3. 建立一個自成一體的 HTML 成品：大型圖片、少量文字，而不是
   以圖示裝飾的長篇文章。
4. 根據證據驗證解說內容，接著分別以寬版與窄版視窗尺寸檢查算繪後的
   成品。

## 受眾

假設受眾對主題毫無基礎，而不是智力低下。使用熟悉的物件、具體的動詞，
以及冷靜成熟的語氣。絕不可顯得幼稚或居高臨下。若省略某項細節會導致
結論反轉，就保留該細節；否則將其留待來源附註說明。

只有在選錯範圍會使解說產生誤導時，才提出一個簡短問題。
否則，選擇最小且實用的範圍，低調說明假設後繼續進行。

## 視覺語法

- 以三到六個場景為佳。每個場景或面板只表達一個概念，並提供清楚的閱讀順序。
- 使用大型圖解、空間關係、移動路徑、時間軸、比例尺或前後
  狀態。裝飾性圖片不算。
- 主要敘事僅使用簡短的標題與標籤。避免段落。讓視覺元素呈現
  順序、數量、歸屬與因果關係。
- 針對模組，呈現輸入 -> 轉換 -> 輸出。針對取捨，呈現獲得與
  失去的項目。針對事件，呈現觸發因素 -> 擴散 -> 影響 -> 復原，並以不同方式標示事實
  與推論。
- 最後以一張圖片和一句話重申核心心智模型。

## HTML 成品

- 使用語意化 HTML，搭配行內 CSS 與 SVG。將所有必要的樣式、圖片與指令碼都保留在
  檔案中；不得依賴 CDN、遠端字型、圖片外連或建置步驟。
- 對不受信任的來源文字進行跳脫處理，而不是插入原始 HTML。
- 讓版面配置具備回應式設計、高對比，且在沒有動畫時仍清楚可讀。遵循
  `prefers-reduced-motion`；不得停用使用者縮放功能，也不得只靠顏色傳達資訊。
- 在窄版寬度下，將水平圖解重新編排為垂直堆疊的場景，而不是縮小
  標籤直到無法閱讀。
- 為每個有意義的視覺元素提供替代文字或無障礙說明。使用簡潔且
  可見的標籤，並搭配 `aria-labelledby`、`<figcaption>` 或同等的語意標記。
- 將引用資料、檔案位置、假設與必要的細節放入名為「來源與假設」的精簡
  `<details>` 區段，讓圖像敘事保持簡潔。
- 只有在互動功能能實質提升理解時，才加入行內 JavaScript。即使是靜態
  成品，也必須能傳達核心解說內容。

若主機提供原生 HTML 成品介面，請優先使用。否則，將檔案寫入
主機原生的暫存目錄，例如使用
`mktemp -d "${TMPDIR:-/tmp}/eli5.XXXXXX"` 建立的目錄；不要將一次性解說內容加入儲存庫。

## 驗證並回傳

透過隔離的瀏覽器或主機預覽開啟結果，絕不可使用真人擁有的瀏覽器。
確認初始畫面能傳達主題、標籤沒有遭到裁切、視覺元素在窄螢幕上仍清晰可辨，
且每一項事實或因果主張都符合原始資料。回傳前先修復缺陷。

回傳成品或其絕對路徑、一句話重點，以及任何重大
不確定性。不要在聊天中重複完整的解說內容。
