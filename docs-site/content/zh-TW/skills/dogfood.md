**實質的可執行增量**是可透過真實使用者進入點或公開進入點操作的行為切片。請在開始下一個切片前實際試用，並在交接或發布前再次試用。測試不等於實際試用：測試驗證的是斷言，而非體驗。

## 盤點可執行的變更

在使用實作成果前，先找出完整的行為清單：

1. 使用
   `BASE=$(PR_BASE_REF="${DOGFOOD_BASE_REF:-}" "${CLAUDE_PLUGIN_ROOT:-.}/scripts/resolve-pr-base.sh")`
   解析目標。這會先選取目前堆疊式 PR 的父分支，再退回遠端預設分支。
2. 檢查從合併基準開始的完整 PR 差異，涵蓋已提交、已暫存、未暫存及未追蹤的變更。請勿將範圍限制於目前工作階段異動的檔案。
3. 將每個可執行成品對應至其變更的行為與真實進入點。技能包含 `SKILL.md`，以及其中參照的指南、資產與指令碼；鉤子與自動化則可透過其實際事件執行。獨立文件、測試與評估不列入必要的體驗涵蓋範圍。

一般的本機工作回合若變更了可執行行為，就應實際試用。完成 PR 或發布前，即使某項可執行行為是在先前的工作階段實作，也要實際試用完整 PR 中的每一項可執行行為。

## 循環

針對目前實作執行**使用 -> 破壞性嘗試 -> 修復 -> 重演**。

### 1. 使用

找出每項變更的行為及其真實使用者進入點。啟動實際實作成果，並親自完成預期流程。檢查可見輸出、狀態轉換、副作用、日誌與主控台，而非從程式碼或測試推斷是否成功。

使用符合正式環境資料形態與基數的代表性實際規模資料。比較預期與實際的數量、排序、時間、狀態及副作用；重複執行足夠長的時間，以顯現穩定狀態或累積行為。

若為錯誤，請先針對尚未修正的行為，完全依照回報者的步驟執行，並記錄確切症狀。若無法重現，請停止診斷、回報已嘗試的內容，並要求提供缺少的環境或證據。請勿修正假設存在的錯誤。

**完成條件：**每項變更的行為都已在其公開介面直接觀察到基準結果。

### 2. 破壞性嘗試

像真實使用者一樣，嘗試讓每項變更的行為出錯：

- **粗心：**空白、無效、過大、重複或順序錯亂的輸入。
- **急躁：**重複操作、重複送出、離開頁面、重新載入、取消或中斷。
- **倒楣：**過期狀態、資料遺失、相依項目失敗、回應緩慢或僅完成一部分。
- **實際資料：**欄位稀疏、ID 重複、租戶或版本混合、長文字、Unicode、時區邊界，以及符合實際情況的基數。
- **效能：**在相關時量測回應時間、網路、算繪、CPU 與記憶體；將證據與明確的預算或基準比較。

套用每個相關面向，並針對每項變更的行為至少嘗試一種合理的破壞方式。優先採用使用者可能做出的行為，而非任意案例。

**完成條件：**已直接觀察預期用途，以及適用的失敗或復原行為。

### 3. 修復

將每個發現的缺陷視為檢查點失敗。若可自動化，請將其轉為 RED 迴歸測試，透過 `/tdd` 修正，並重新執行聚焦的自動化檢查。任何程式碼變更都會使先前的實際試用證據失效。

**完成條件：**沒有任何已觀察到的缺陷仍未解決或遭到默默延後。

### 4. 重演

從真實進入點重新啟動，並在目前實作上重複預期流程與每次破壞性嘗試。若為錯誤修正，請重演修正前完全相同的重現步驟，確認回報的症狀已消失，且未破壞相鄰行為。

**完成條件：**目前的可執行狀態（而非較早的建置版本）通過完整循環。

## 選擇真實進入點

| 變更 | 操作方式 |
|---|---|
| Web 或儀表板 | 執行應用程式；瀏覽、點選、輸入、重新載入，並檢查主控台／網路 |
| CLI 或 TUI | 使用實際、無效及遭中斷的輸入來叫用已建置的命令 |
| API 或工作程序 | 傳送真實請求／事件，並檢查回應與副作用 |
| 程式庫 | 從最小的真實使用端使用其公開 API |
| 鉤子或自動化 | 針對代表性測試資料觸發實際事件 |
| 技能或代理程式指令 | 在全新且貼近實際的工作上使用；檢查行為，而非文字內容 |
| 示範或原型 | 操作可執行成品，直到其欲驗證的問題獲得可觀察的答案 |

優先使用專案原生工具。僅在使用者授權委派時使用全新的代理程式。

## 執行紀錄

將進入點、操作與觀察結果連結至目前實作。回報：

`Verdict: PASS | FAIL | BLOCKED`

- **進入點：**確切的命令、URL、事件或使用端
- **操作：**預期流程與破壞性嘗試
- **觀察：**資料形態／規模、數量／排序／時間、輸出、狀態、副作用、主控台／網路／日誌
- **修復：**發現的缺陷、新增的測試、完成的修正、重演結果
- **限制：**未嘗試的行為及原因

在最終回應中包含完整的結構化執行紀錄。PASS 必須提供目前實作中每項變更行為的體驗證據。FAIL 表示仍有已觀察到的缺陷。BLOCKED 須指出缺少的存取權、環境、硬體或安全限制，以及接下來所需的證據。
