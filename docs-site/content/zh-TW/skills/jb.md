從一個面向審查：這項變更現在是否服務真實的呼叫端、能否在使用者實際執行的環境中證明有效，
並且以可逆的方式落地？時間有限；快速交付、快速失敗，以小幅度持續迭代。
可獨立執行，也可在 `/review` 中以 **jb 審查角色**執行（300 字）；程式碼缺陷仍由 `/review` 處理。

預設核准：這個審查角色背後的實務中，要求變更的 PR 不到 1%。
只針對 P1 清單中的問題阻擋合併，絕不因為小瑕疵、投入心力或差異大小而阻擋。

## 1. 選擇一個類別 [#1-pick-one-lane]

閱讀 PR 標題、內文、工作項目與差異。指定一個主要類別：

| 類別 | 值得投入時間的理由 | 預期佐證 |
|---|---|---|
| `ktlo` | 維持正常運作、減少繁瑣作業、節省成本 | 能消除的事故、故障或支出；若有變更前後的數據，則提供比較 |
| `qol` | 改善 CI、開發者體驗、效能、可靠性與聲譽 | 誰的工作循環縮短了，或哪個使用者痛點消失了，並提供量測結果 |
| `growth` | 客戶、商機或上線需求所推動的新能力；創造營收 | 目前受阻的呼叫端、合併後能做的事、准入條件與驗收情境 |
| `taste` | 透過刪除、統一或自動產生，降低下一次變更的成本 | 刪除了什麼或杜絕了什麼，以及讓哪個後續使用方不再受阻 |

機械式 PR（版本升級、產生檔同步、還原變更、文件錯字修正）屬於 `ktlo`，無須文字
說明即可成立。前置工作應歸入它所支援的使用者可見變更類別，並指明該變更。
同一個 PR 若包含互不相關的類別，就應要求拆分。請對照 RULES.md 的**類別**判斷依據。

## 2. 檢驗該類別的佐證 [#2-test-the-lanes-evidence]

只有當 PR、工作項目或差異明確指出具體問題或呼叫端時，才標記為**有充分理由**；
需要自行推論的價值屬於**佐證薄弱**。**缺乏理由**：沒有受益者、沒有問題，或只是推測性的
通用化。即使指明受益者，也不能合理化擅自覆寫呼叫端要求的內容
（模型、身分、區域、值），或偏離標準契約；這充其量也只是佐證薄弱。請問：

- `ktlo`：「如果不做，什麼會壞掉、觸發值班通知，或產生費用？」
- `qol`：「誰的工作循環會縮短，我們要如何看出來？」
- `growth`：「目前哪個呼叫端受阻，合併後它就能做什麼？」
- `taste`：「這會刪除什麼，接下來又會降低什麼的成本？」

## 3. 檢查跨類別規則 [#3-check-cross-cutting-rules]

載入 [RULES.md](https://github.com/malinskibeniamin/skills/blob/main/jb/RULES.md) 中對應的章節；套用 S/A，只有明確違反時才標記 B，
C 則僅在摘要中提及：

- **一律檢查**：範圍、佐證，以及核准與負責人決策清單。
- **推出**（功能旗標、遷移、預設值、部署、公開 API、不可逆操作）：交付。
- **供使用方取用的輸出**（API、UI、CLI、工具結果、錯誤、指標）：契約。
- **新增介面或抽象概念**（欄位、選項、模式、服務、產生器）：品味。
- **支出**（模型 token、運算資源、CI 分鐘數、供應商配額、繁瑣作業）：成本。

## 嚴重程度 [#severity]

- **P1**：非微小變更卻無法辨識受益者或問題（`unjustified`）；
  推測性的範圍：目前沒有呼叫端使用的欄位、選項、抽象概念、服務或模式；
  `growth` 或高風險變更缺乏可證偽的驗收條件或驗證途徑；
  不可逆的變更卻沒有功能旗標、回復機制，或已記錄的負責人決策。
- **P2**：類別佐證為 `thin`，且有具體後果；違反 S/A 規則。預設關閉、
  需主動啟用，或僅供開發使用的新增功能，其佐證缺口降為 P3。
- **P3**：B/C 提醒、成本更低的拆分方式、後續事項；僅列於摘要。

最多回報三項發現，優先列出會影響合併決策的問題。需要升級交由負責人處理時，請指明不利
情境與所需決策。

## 輸出 [#output]

一律以一行判定開頭：

`jb: <lane> -- <justified|thin|unjustified> -- <beneficiary and evidence, at most 20 words>`

接著使用 `[P1|P2|P3] <file:line or PR body> <rule-id> -- <consequence>; <smallest fix, or the
sentence the PR body is missing>`。審查計畫時，請引用章節，並將缺少的驗收
條件寫成可證偽的情境。若完全通過，只輸出判定行。
