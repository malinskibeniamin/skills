這是任何供代理程式取用之文件的參考指南：技能、`AGENTS.md`、`CLAUDE.md`，或透過指標連結到的文件。封裝方式各有不同，寫作原則則一致。目標是建立可預期的流程，而非產出完全相同的結果。

撰寫技能時，請閱讀 [SKILL-MECHANICS.md](https://github.com/malinskibeniamin/skills/blob/main/writing-for-agents/SKILL-MECHANICS.md)，以瞭解 frontmatter、叫用方式的選擇，以及路由器。

## 情境指標

**情境指標**是已載入的文字，會指出情境之外的資料，並編碼應在何時取用該資料。技能描述與 `AGENTS.md` 中指向另一份文件的一行文字，本質上是相同的物件。決定代理程式能否可靠遵循指標的是措辭，而非指標目標。

指標會說明資料的內容，以及觸發取用的不同**分支**。由於每次都會載入的指標會在每一輪耗用 token 與注意力：

- 在開頭放置有力的引導詞。
- 每個分支保留一項觸發條件；同一分支的同義詞屬於重複內容。
- 移除目標文件本身已表明的身分資訊。

在將弱指標的目標內容直接內嵌之前，先強化該指標。

## 兩種負載

- **情境負載**——每次都會載入，並在每一輪耗用 token 與注意力的資料。
- **認知負載**——人員必須記得有哪些資料存在，以及何時叫用它們。

放在指標後方的資料能避免正文層級的情境負載，但仍需付出指標本身一行文字的成本。沒有指標的資料則完全仰賴人員記憶。認知負載是人員自主性的代價，不應盲目追求將其數值降到最低。

## 資訊階層

文件混合了兩類內容：**步驟**，即代理程式依序執行的工作；以及**參考資料**，即代理程式查閱的規則與事實。請將每個項目放在有充分理由支持的最淺層級：

1. **檔案內步驟**——主要的依序執行動作。
2. **檔案內參考資料**——可立即派上用場的輔助資料。
3. **揭露式參考資料**——透過情境指標載入的另一個檔案。

**漸進式揭露**會將資料沿此階梯向下移動。每個分支都需要的內容應直接內嵌；只有部分分支需要的內容則應揭露。若參考資料掩埋了必要步驟，這就是執行差異的缺陷，而不只是文件過長。

**共置**是指在選定概念所屬的階層後，將其定義、規則與注意事項放在一起。分散會割裂同一層意義；重複則會反覆陳述。

## 步驟與完成條件

每個步驟都應以一項**完成條件**作結：

- **明確性**——代理程式能否區分已完成與未完成？模糊的界線容易導致過早宣告完成。
- **要求強度**——此條件要求涵蓋每個相關項目，還是僅要求提供一份清單？

先明確化界線。如果某個無法再降低模糊程度的步驟仍被草率執行，請沿著真正的情境邊界拆分流程，避免後續步驟持續將注意力向前拉扯。要求強度會驅動代理程式實際投入的查核工作，無須另加「務必詳盡」之類的指示。

## 何時拆分

只有在完成後才執行、但提前可見的步驟會導致過早宣告完成時，才拆分流程。技能特有的叫用拆分方式請參閱 [SKILL-MECHANICS.md](https://github.com/malinskibeniamin/skills/blob/main/writing-for-agents/SKILL-MECHANICS.md)。

## 引導詞

**引導詞**是代理程式用來思考的精簡預訓練概念，例如 _tracer bullet_、_frontier_ 或 _red_。它能濃縮重複說明，並同時固定正文中的執行方式與指標中的叫用方式。應優先採用既有詞彙，而非另造一個還需要額外定義的新詞。

找出反覆出現、可由一個有力詞彙取代的片語。這樣做能減少 token，並建立更鮮明的檢索鉤點。

**否定指令**是相鄰的失敗模式：禁令會啟動它所提及的行為。請改為提示要達成的**正向**目標。只有在禁令屬於無法以正向方式表述的硬性護欄時才予以保留，並搭配說明應採取的做法。

## 刪減

- 每項意義只保留一個單一事實來源。重複內容會放大其顯著性與維護成本。
- 將環境視為事實來源：指令碼、設定、配置與 `--help` 已能回答成本低廉的查詢。文件是一種快取；僅應保留查詢成本高昂的資訊、未明文記載的慣例、背後原因，以及隱藏的陷阱。
- 檢查每一行是否相關。未經刪減的文件會堆積過時的沉澱內容。
- 逐句找出無實際作用的內容。如果某項指示相較於模型的預設行為不會造成任何改變，就刪除該句，而非加以潤飾。
- 將內容無限制擴張視為資訊階層失靈：依分支揭露內容，或拆分確實會被草率執行的流程。
