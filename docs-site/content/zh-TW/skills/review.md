審查直到 `HEAD`。保留唯一所有者；委派必須明確授權。不要編輯、提交、推送或發布。
發布評論需要明確意圖。

## 審查約定

- **目標**：判斷完整差異是否實現預期結果且沒有可信缺陷。
- **約束**：僅限差異引入的問題；將標準問題與產品/規格缺口分開；
  生成檔案是證據。
- **驗證**：追溯來源。親自透過真實入口試用每項可執行變更；
  測試不能替代體驗。
- **停止**：涵蓋每個表面；發現必須包含證據、後果、優先順序、修正和驗證方法。

僅在缺少固定點時詢問。否則設定
`BASE=$(PR_BASE_REF="${REVIEW_BASE:-}" "${CLAUDE_PLUGIN_ROOT:-.}/scripts/resolve-pr-base.sh")`，
再檢查完整差異和日誌。

## 證據迴圈

**檢查 -> 驗證 -> 分類 -> 綜合。**

### 檢查

1. 閱讀請求/規格、規則、完整差異、呼叫點和行為。不要讓 PR 摘要凌駕於程式碼。
2. 對每個變化的假設，反向追蹤權威生產者、模式、
   儲存、消費者和公共表面。按領域概念、欄位和輸出
   值搜尋，不只搜尋變更符號。
3. 用相關未變程式碼中的獨立產物、基線、
   近期歷史、執行時證據和夾具檢驗意外情況。比較夾具與生產資料形狀。
4. 為一種可信碰撞構造行為反例。對映許可權和可見
   表面；跳過格式化工具負責的樣式和既有缺陷。
5. 詢問：即使測試透過，仍可能錯在哪裡？

### 驗證

- 對照原始碼、模式、第一手文件或最小可執行檢查復現。
- 當安全性取決於一項非本地事實時，使用 `/blast-radius`；攜帶證據，而非敘述。
- 使用具有代表性的真實規模資料，執行預期路徑和一個可信的失敗或恢復路徑。
  觀察控制檯、網路、日誌和響應時間；若不安全或無法使用，說明阻礙。
- 檢查測試完整性：公共行為、RED、斷言、覆蓋範圍，以及沒有固定時長等待。
  除非文字是公共輸出，否則原始文字檢查不算覆蓋；刪除，或改以
  公共接合面取代。語法使用靜態分析。
- 按必要行為、語義密度、領域清晰度、可信
  風險和已證規模質疑新增內容。絕不以 LOC 為最佳化目標，也不鼓勵程式碼高爾夫。

僅在差異提供證據時新增表面專項審查：

| 表面 | 檢查 |
|---|---|
| 面向客戶的 UI/CLI/報告 | 渲染、狀態、文案、鍵盤/a11y、控制檯、視口 |
| 安全/隱私/資料丟失 | 信任、授權、金鑰、注入、恢復 |
| API/模式/SQL/PostgreSQL | 相容性、遷移、生成輸出、實際方言 |
| Go/併發/工作流 | 所有權、取消、競態、重試、冪等 |
| 依賴/外部 API | 第一手文件、版本、鎖檔案、安全通告 |

### 分類

發現必須由差異引入、有實際影響、可復現或有具體路徑，定位到最精確的變更行，
並配最小安全修復。

- **P0**：暴露、資料丟失、中斷或核心流程不可用。
- **P1**：使用者迴歸、契約破壞、錯誤成功或嚴重 a11y 缺陷。
- **P2**：影響較低但有用且範圍明確的修正。
- 行內評論中省略未來可選工作和潤色。

沒有測量或結構邊界，不報告效能。沒有可信風險，不報告邊緣情況。
證據也可以支援有理拒絕。

### 綜合

以發現開頭，按根因去重。只給出路徑、影響、修正和驗證
步驟；省略讚美與敘述。重新審查時標記每條舊發現的狀態。

## 深度模式

使用 `--deep` 時沿用同一迴圈並建立完整適用性清單。閱讀
[DEEP-AUDIT.md](https://github.com/malinskibeniamin/skills/blob/main/review/DEEP-AUDIT.md)；覆蓋全部表面，不自動增加智慧體。

## 輸出

閱讀 [REFERENCE.md](https://github.com/malinskibeniamin/skills/blob/main/review/REFERENCE.md) 以了解術語和結構。報告
`[P0|P1|P2] <file:line> <title> - <evidence, consequence, correction, verify command>`。
附加 `entrypoint, data, actions, observations, timing, limits`、固定點、模式、計數、
結論和剩餘限制。無發現時只返回結論和剩餘限制。
