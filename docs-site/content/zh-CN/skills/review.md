## 审查约定

- **目标：** 判断完整差异是否实现预期结果且没有可信缺陷。
- **约束：** 只报告差异引入且可操作的问题；将标准问题与产品/规格缺口分开；生成文件是证据，不是编辑目标。
- **验证：** 将主张追溯到来源。亲自通过真实入口试用每项可运行变更；测试支持体验，但不能替代体验。
- **停止：** 每个适用表面均已覆盖；每条发现都有证据、后果、优先级、修正和验证方法。

缺少比较固定点时询问。否则设置
`BASE=$(PR_BASE_REF="${REVIEW_BASE:-}" "${CLAUDE_PLUGIN_ROOT:-.}/scripts/resolve-pr-base.sh")`，
再检查直到 `HEAD` 的完整差异和日志。

## 证据循环

**检查 -> 验证 -> 分类 -> 综合。**

### 检查

1. 阅读请求或规格、仓库规则、完整差异、调用点和行为。不要让 PR 摘要凌驾于代码。
2. 对每个变化的假设，反向追踪权威生产者、模式、存储、消费者和公共表面。按领域概念、字段和输出值搜索，不只搜索变更符号。
3. 用未变代码中的独立产物、基线、近期历史、运行时证据和夹具检验意外主张。比较夹具与生产数据形状。
4. 为一种可信碰撞构造行为反例。映射权限和可见表面；跳过格式化工具负责的样式和既有缺陷。
5. 询问：即使测试通过，仍可能错在哪里？

### 验证

- 对照源码、模式、当前第一手文档或最小可执行检查复现。
- 使用具有代表性的真实规模数据，执行正常路径和一个可信的失败或恢复路径。观察控制台、网络、日志和响应时间；无法安全运行时说明阻碍。
- 检查测试完整性：公共行为、修复前 RED、有效断言、覆盖未削弱、无固定时长等待。
- 按必要行为、语义密度、领域清晰度、可信风险和已证规模质疑新增内容。不要以 LOC 或代码高尔夫为目标。

仅在差异提供证据时添加表面专项审查：

| 表面 | 检查 |
|---|---|
| 面向客户的 UI/CLI/报告 | 渲染、状态、文案、键盘/a11y、控制台、视口 |
| 安全/隐私/数据丢失 | 信任边界、授权、密钥、注入、恢复 |
| API/模式/SQL/PostgreSQL | 兼容性、迁移、生成输出、实际方言 |
| Go/并发/工作流 | 所有权、取消、竞态、重试、幂等 |
| 依赖/外部 API | 第一手文档、版本、锁文件、安全通告 |

### 分类

发现必须由差异引入、有实际影响、可复现或有具体路径，定位到最精确的变更行，并配最小安全修复。

- **P0：** 暴露、数据丢失、中断或核心流程不可用。
- **P1：** 用户回归、契约破坏、错误成功或严重 a11y 缺陷。
- **P2：** 影响较低但有用且范围明确的修正。
- 默认不在行内评论中报告未来可选工作和润色。

没有测量或结构边界，不报告性能；没有可信风险，不报告边缘情况。证据也可以支持有理拒绝。

### 综合

以发现开头，按根因去重。只给出路径、影响、修正和验证步骤；省略赞美与叙述。重新审查时标记旧发现的状态。

## 深度模式

使用 `--deep` 时沿用同一循环并建立完整适用性清单。阅读 [DEEP-AUDIT.md](https://github.com/malinskibeniamin/skills/blob/main/review/DEEP-AUDIT.md)；覆盖全部表面，不自动增加智能体。

## 输出

[REFERENCE.md](https://github.com/malinskibeniamin/skills/blob/main/review/REFERENCE.md) 定义术语和结构。格式：`[P0|P1|P2] <文件:行> <标题> - <证据、后果、修正、验证命令>`。
附加 `entrypoint, data, actions, observations, timing, limits`、固定点、模式、计数、结论和剩余限制。无发现时只返回结论和剩余限制。
