TDD 保护有意义的行为，而不是对每个有改动的文件征税。

对于错误、回归以及新增或变更的契约，请使用红灯 -> 绿灯 -> 重构：
包括领域规则、分支、状态转换、解析、验证、异步副作用，以及一旦失败便会
造成影响的集成行为。类型、重新导出、声明式连接、静态文案和样式，以及
保持行为不变的删除，可能只需运行现有的针对性验证。

覆盖率可以揭示疑似盲区，但绝不是目标，也不能成为凭空编写测试的理由。

## 测试接缝与反模式

- **接缝**：在公共边界进行测试。编写测试前，先明确记录接缝；如果问题本身或现有约定未能清楚表明接缝，请与用户确认预先商定的接缝。不要针对未经确认的内部实现编写测试。
- **同义反复的测试**：不要以与代码相同的方式重新计算预期值；应使用独立的事实来源：已知正确的字面值、完整推导的示例、夹具、规范或观测到的行为。
- **水平切片**：不要先写完所有测试，再写全部实现。批量测试检验的是想象中的行为。正确做法是垂直切片——完成一个红灯->绿灯的测试和实现，然后重复。

如果公共接缝本身尚不明确，请使用 `/codebase-design`；不要为了方便测试而
凭空设计内部接缝。

## 工作流

### 0. 契约

- 明确公共接口处可观测行为的名称。遵循项目的领域术语表和 ADR。
- 选择一旦该行为失效就会失败的最小测试。一个测试可以验证多行代码。
- 仅针对独立且可信的风险添加其他用例，不要覆盖每个可以想象的边缘情况。
- 当一个不变量横跨高基数输入或可达状态序列时，请阅读
  [基于属性的测试](https://github.com/malinskibeniamin/skills/blob/main/tdd/PROPERTY-BASED-TESTING.md)。必须使用独立的判定依据，并确保失败可以重放。
- 对于长期运行的浏览器页面中的资源生命周期契约，请使用可重复的
  往返操作，并阅读 [SPA 浸泡测试](https://github.com/malinskibeniamin/skills/blob/main/e2e-testing/SOAK-TESTING.md)。全新的
  浏览器上下文无法暴露多次交互后累积的问题。
- 如果契约由第三方行为定义，请使用 `/read-the-damn-docs`。
- 当接缝或测试形式不明确时，请阅读 [tests.md](https://github.com/malinskibeniamin/skills/blob/main/tdd/tests.md)。

### 1. 红灯

- 编写一个行为测试，并确认它因预期原因而失败。
- 优先使用真实的公共接口；仅模拟无法在本地运行的外部边界。

### 2. 绿灯

- 编写能够通过测试的最小且直观的实现。
- 优先删除或复用；然后优先使用语言、平台或已安装的依赖项，而非自定义机制。
- 遵循相关 `exemplars/` 文件的清晰度和约定，而不是它的规模。

### 3. 重构

- 仅当含义变得更清晰或真正的重复得以消除时，才改进命名和结构。
- 始终保持绿灯。绝不能仅为通过测试而削弱行为断言。
- 标记耗时超过 500ms 的单元测试和超过 2s 的集成测试；优先使用批量输入，而不是逐次模拟按键。
- 对实质性的可运行行为执行 `/dogfood`；观测到的缺陷将成为下一个红灯。

### 4. 重复

仅在存在另一个必需契约或独立且可信的风险时重复。

进行开发时，请监控 `vitest --watch`。当变更会创建异步工作时，请使用基于条件的
等待和 `--detectAsyncLeaks`。

## 测试分类

| 后缀 | 用途 | DOM？ |
|--------|---------|------|
| `.test.ts` | 单元测试——纯逻辑 | 否 |
| `.test.tsx` / `.integration.tsx` | 集成测试——渲染组件 | 是 |
| `e2e/*.spec.ts` | 端到端测试——Playwright 浏览器 | 浏览器 |

## 视觉回归测试

当路由新增尚未覆盖的客户可见行为，且项目使用
`@vitest/browser` 时，请添加最小且实用的 `*.browser.test.tsx`。对于
布局、重定向和纯声明式路由则跳过。

## 完成标准

- 相关测试通过且没有警告。
- 异步变更不存在泄漏的工作或基于固定时长的等待。
- 测试验证的是行为而非实现，因此能够经受内部重构。
- 不存在仅为提高覆盖率而添加的冗余用例。

有关基于条件的等待、选择器、传送门、模拟、诊断和针对性韧性示例，请参阅
[REFERENCE.md](https://github.com/malinskibeniamin/skills/blob/main/tdd/REFERENCE.md)。
