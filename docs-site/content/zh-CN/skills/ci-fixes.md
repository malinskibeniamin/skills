以更少计算资源，更快获得有意义的 CI 通过结果，同时保留回归保护。
优化从提交到最后一项必需检查完成的时间，而不只是单项测试时长。
遵守用户要求的终点：审计和计划保持只读；仅在要求实施时修改。
不要顺带创建定时任务、购买运行器、更改分支保护或启动代理。

## 建立基线

1. 确认目标仓库、分支、工作流、可复用及组合操作、脚本、测试配置、必需检查和相关指令文件。检查实际命令。
2. 收集近期可比较的运行，包括失败和重试：提交及运行链接、排队时间、任务依赖、准备/构建/测试/上传时间、缓存状态、运行器资源、工作进程数、分片时长、测试数量和首次尝试的失败。使用平台原生日志和报告；缺少历史表示未知，不是速度或可靠性的证据。
3. 绘制从前置准备到最终必需结果的关键路径。区分实际耗时与总运行器分钟数及成本；记录样本量和环境。

## 选择最小有效改动

完整阅读 [21 项审计检查](https://github.com/malinskibeniamin/skills/blob/main/ci-fixes/REFERENCE.md)。评估每一项；为各适用任务记录**采用**、**拒绝**、**推迟**或**不适用**及其证据。
不要仅因某种优化可用就实施。按实测关键路径节省量、计算资源节省量、可信度和实施维护风险排序。
未知事项需要小规模实验，而不是编造估算。绝不为让任务同时结束而拖慢快速任务。

仅为当前工作加载辅助指引：

- 修改工作流：[CI 维护](https://github.com/malinskibeniamin/skills/blob/main/t3code-skills/ci-maintenance/SKILL.md)，包括其规范源文件和信任边界规则。确保凭据、缓存、制品和 fork 安全。
- 精简测试：[测试审计](https://github.com/malinskibeniamin/skills/blob/main/test-audit/SKILL.md)。删除前明确保留的契约及其主要测试；速度和行覆盖率本身不足以支持删除。
- 诊断不稳定测试：[错误诊断](https://github.com/malinskibeniamin/skills/blob/main/diagnosing-bugs/SKILL.md)。复现首次尝试的失败，修复实际实现或测试基础设施；重试通过不等于修复。
- 升级工具：[依赖升级](https://github.com/malinskibeniamin/skills/blob/main/upgrade-dependency/SKILL.md)。执行时通过一手资料核实当前稳定版本、迁移指南和运行器兼容性。

实施时每次只修改一个相关瓶颈。新增行为和修复从失败的公共契约测试开始；配置和文档使用可执行验证，而不是搜索指令文本的测试。保留无关改动。

## 证明改进

- 运行工作流语法检查、仓库门禁和受影响测试。验证缓存未命中、命中及失效路径；更改测试选择时，与完整测试集参考结果比较。验证失败传播、分片缺失和必需检查完成状态。
- 除被测变量外，前后基准使用相同工作负载、运行器、工具版本、工作进程数和缓存条件。重复运行；报告原始时长、样本数、有意义的中位数和尾部情况，并单独报告运行器分钟数及排队时间。
- 更改工作进程、隔离或分配方式后，以拟采用的并发度重复及打乱顺序运行。检查内存、CPU、不稳定测试和共享状态竞争。
- 精简测试时，使用相同插桩、阈值、排除项和源代码分母，比较完整保留测试集的行及分支覆盖率。保留独特故障检测能力和关键用户流程，而不只是百分比；使用针对性的负向对照或变异测试。
- 运行与变更契约相符的完整回归检查。明确说明仅能在托管环境验证或无法验证的部分；本地成功不能证明 GitHub CI 成功。

通过意味着正确的工作确实执行了。保持错误可见：不吞掉退出码，不使用 `continue-on-error`，不削弱断言或覆盖率，不永久跳过或隔离测试，也不用重试掩盖不稳定测试。绝不将失败测试移到夜间运行并声称已修复。

## 交接

先给结果及其局限。包括关键瓶颈、全部 21 项检查的决策、前后证据及样本和缓存条件、测试契约归属变化及删除理由、版本和来源核实日期、实际命令和运行链接、未解决风险及回滚方式。
区分实测收益和提议实验。详细记录放在仓库现有的证据位置；总结而不是倾倒日志。
