**实质性可运行增量**是指可通过真实用户入口或公共入口执行的行为切片。在开始下一个切片之前，以及移交或发布之前，都要对其进行内部试用。测试不等同于内部试用：测试验证的是断言，而非实际体验。

## 盘点可运行的变更

在使用实现之前，先确定完整的行为清单：

1. 使用
   `BASE=$(PR_BASE_REF="${DOGFOOD_BASE_REF:-}" "${CLAUDE_PLUGIN_ROOT:-.}/scripts/resolve-pr-base.sh")`
   确定目标。这会优先选择当前堆叠式 PR 的父分支，然后再回退到远程默认分支。
2. 检查从合并基点开始的完整 PR 差异，包括已提交、已暂存、未暂存和未跟踪的变更。不要将范围限制在当前会话中改动的文件。
3. 将每个可运行产物映射到其变更的行为和真实入口。技能包括 `SKILL.md` 及其引用的指南、资源和脚本；钩子和自动化应通过其实际事件运行。独立文档、测试和评测无需纳入体验覆盖范围。

对于普通的本地操作轮次，如果该轮次更改了可运行行为，就要进行内部试用。在完成 PR 或发布之前，即使某项可运行行为是在较早的会话中实现的，也要对完整 PR 中的每项可运行行为进行内部试用。

## 循环

针对当前实现执行**使用 -> 破坏性尝试 -> 修复 -> 重放**。

### 1. 使用

识别每项发生变更的行为及其真实用户入口。启动实际实现并亲自完成预期流程。检查可见输出、状态转换、副作用、日志和控制台，而不是根据代码或测试推断成功。

使用符合生产环境数据形态和基数的代表性真实规模数据。比较预期与实际的数量、顺序、耗时、状态和副作用；重复运行足够长的时间，以暴露稳态或累积行为。

对于缺陷，首先针对未修复的行为严格执行报告者提供的步骤，并记录确切症状。如果无法复现，请停止诊断，报告已尝试的操作，并请求缺失的环境或证据。不要修复臆测的缺陷。

**完成条件：**每项发生变更的行为都已在其公共边界获得直接观察到的基线。

### 2. 破坏性尝试

像真实用户一样，尝试破坏每项发生变更的行为：

- **粗心操作：**空、无效、超大、重复或乱序输入。
- **急躁操作：**重复操作、重复提交、离开页面、重新加载、取消或中断。
- **不利情况：**过期状态、数据缺失、依赖项故障、响应缓慢或部分完成。
- **真实数据：**稀疏字段、重复 ID、混合租户或版本、长文本、Unicode、时区边界和现实的基数。
- **性能：**在相关情况下测量响应时间、网络、渲染、CPU 和内存；将证据与明确的预算或基线进行比较。

应用所有相关视角，并针对每项发生变更的行为至少进行一次合理的破坏性尝试。优先考虑用户可能执行的操作，而不是任意构造的情况。

**完成条件：**已直接观察预期用途以及适用的失败或恢复行为。

### 3. 修复

将发现的每个缺陷视为检查点失败。在可以自动化时，将其转化为处于 RED 阶段的回归测试，通过 `/tdd` 修复，并重新运行针对性的自动检查。代码变更会使先前的内部试用证据失效。

**完成条件：**不存在尚未解决或被悄然推迟的已观察缺陷。

### 4. 重放

从真实入口重新启动，并在当前实现上重复预期流程以及每次破坏性尝试。对于缺陷修复，重放与修复前完全相同的复现步骤，并确认报告的症状已消失，同时未破坏相邻行为。

**完成条件：**当前可运行状态（而不是较早的构建）经受住了完整循环。

## 选择真实入口

| 变更 | 执行方式 |
|---|---|
| Web 或仪表板 | 运行应用；导航、点击、输入、重新加载，并检查控制台/网络 |
| CLI 或 TUI | 使用现实、无效和中断的输入调用构建后的命令 |
| API 或工作进程 | 发送真实请求/事件，并检查响应及副作用 |
| 库 | 从最小化的真实使用方调用其公共 API |
| 钩子或自动化 | 针对代表性测试夹具触发实际事件 |
| 技能或智能体指令 | 在全新的现实任务中使用；检查行为，而不是文字说明 |
| 演示或原型 | 操作可运行产物，直到其问题得到基于观察的答案 |

优先使用项目原生工具。仅当用户授权委派时，才使用新的智能体。

## 凭据

将入口、操作和观察结果与当前实现绑定。报告：

`Verdict: PASS | FAIL | BLOCKED`

- **入口：**确切的命令、URL、事件或使用方
- **操作：**预期流程和破坏性尝试
- **观察结果：**数据形态/规模、数量/顺序/耗时、输出、状态、副作用、控制台/网络/日志
- **修复：**发现的缺陷、添加的测试、实施的修复、重放结果
- **限制：**未尝试的行为及其原因

在最终响应中包含完整的结构化凭据。PASS 要求当前实现的每项变更行为都有体验证据。FAIL 表示仍存在已观察到的缺陷。BLOCKED 需说明缺失的访问权限、环境、硬件或安全约束，以及下一步所需的证据。
