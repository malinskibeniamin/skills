從目前負責的差異或 PR 開始，閱讀並執行[作者交付工作流程](https://github.com/malinskibeniamin/skills/blob/v4.45.0/shared/delivery-workflow.md)。驗證、實際試用、自我審查並發布後，執行[自動維護](https://github.com/malinskibeniamin/skills/blob/v4.45.0/shared/delivery-workflow.md#automatic-pr-maintenance)：修復 CI、處理回饋與衝突，驗證並推送；透過單一、已授權的主機喚醒機制繼續工作。

維持單一負責人。先前明確要求僅在本機作業、僅提交、僅推送、僅發布或不監控時，這些停止條件優先。保留草稿狀態。合併、變更整個堆疊、委派、更換模型及安裝常駐設定，都必須在授權範圍內。

實作尚未完成時，載入 [development-lifecycle](https://github.com/malinskibeniamin/skills/blob/v4.45.0/development-lifecycle/SKILL.md)。
