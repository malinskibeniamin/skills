# Bend laws reference

Written against Bend 2.0.37. `bend guide` is the source of truth for syntax; this file
holds the traps the guide does not warn about and the patterns that close proofs.

## Gate

| Command | Passes when |
|---|---|
| `bend PROOF.bend` | exit 0 and the line `ALL PROOFS CHECK`; otherwise `SOME PROOFS FAIL` with the law, expected and observed terms |
| `bend PROOF.bend --verdict` | the same, rechecked by the BendTT kernel, which has a Lean proof that no accepted def has type `Empty` |

Releases before 2.0.32 printed `All terms check.`; `check.sh` accepts only the current
verdict. The plain checker has no proof, and the parser and the translation into the
kernel are unproven. Run `--verdict` in CI when you can.

`--verdict` needs Lean v4.34.0 (`elan toolchain install leanprover/lean4:v4.34.0`), or
`$BENDTT` pointing at a built kernel. The first run builds the kernel; cache it.

## Syntax traps

- Patterns on imported constructors need the module prefix and braces: `case P.Yes{}:`.
  A bare name binds everything (bendlang/bend#1328).
- A `match` scrutinises only parameters or pattern-bound variables, in binder order. To
  split hints in another order, write a lemma whose parameters come in match order and
  call it from the law's def.
- There is no `if`: match on `True{}` and `False{}`.
- Values are affine: mark a parameter `+x` to use it twice.
- `bend f.bend -o f.js` needs a `main`. `-o f.mjs` needs none: its default export holds
  the non-IO defs, so `(await import("./f.mjs")).default.decide({$: "Auto"}, {$: "Missing"})`
  returns `{$: "Ask"}`. A `Nat` crosses to JavaScript as a number up to 2^53.

## Proof patterns

- `{==}` closes a law when both sides compute to the same value. A law over inputs the
  function never inspects closes with `{==}` directly.
- When the result depends on an input, split it. Split only where it matters: a `_` arm
  is enough where every case computes the same, and the checker prints the stuck
  expected and observed terms where a split is missing.
- For "whatever mode A allows, mode B allows" or "allowed implies declared", state the law
  with an `implies` helper defined in `LAWS.bend`, and prove it with a lemma that
  enumerates the model's branches.

```python
# LAWS.bend: the helper lives here, not in the model
def implies(p: Bool, q: Bool) -> Bool:
  match p:
    case True{}:
      q
    case False{}:
      True{}

# LAW: auto mode never runs a tool that reaches the open world
law auto_never_runs_external:
  for ro: P.Hint
  for de: P.Hint
  {P.decide(P.Auto{}, P.Present{ro, de, P.Yes{}}) == P.Ask{} : P.Action}
```

```python
# PROOF.bend: open world wins in every destructive arm, so split only `de`
def Laws.auto_never_runs_external(ro, de):
  match de:
    case P.Yes{}:
      {==}
    case P.Unset{}:
      {==}
    case P.No{}:
      {==}
```

## Oracle

`oracle.bend` imports the model, enumerates every input with structural recursion over
lists of constructors, and prints one line per input after the header
`# @generated by oracle.bend. DO NOT EDIT: run laws/check.sh --write`. Show functions map
each constructor to the string the shipped code uses, so the unit test compares
strings without translation.

## Upgrading Bend

Copy `VER` and the four sha256 sums from the release notes into `laws/install-bend.sh`,
reinstall, and run `laws/check.sh`. Read the release's breaking changes for gate output,
import rules, and JavaScript interop.
