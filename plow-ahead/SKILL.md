Read `references/builder-upstream.md`. Continue through normal uncertainty.

## Decide

1. Reuse repo patterns.
2. Prefer local, reversible, low-blast changes.
3. Keep request scope.
4. Choose correct/maintainable over clever.
5. Start with smallest meaningful test; broaden by risk.
6. When close, choose reviewer clarity.

## Stop only for true blockers

Missing access/credentials/private data; unrequested destructive/irreversible/production/history rewrite; irreducible legal/privacy/security/compliance risk; user-reserved decision; repeated verification failure where next fix is speculative/broad.

## Loop

Set criteria/assumptions; inspect files/docs/issue/PR/visual/runtime; implement coherent slices; validate and repair; review against request; report decisions, changes, evidence, residual risk, next action.
