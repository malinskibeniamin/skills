## Methodology

- Script: `scripts/harness-bench.sh`.
- Worktrees: the script clones the source repo into a temp dir first because this sandbox cannot write to the source `.git`; from that clone it creates real worktrees at `/tmp/bench-main` and `/tmp/bench-branch`, including `git worktree add /tmp/bench-main main`, then cleans them up.
- Hook timing:
  - Synthetic `.tsx` edit adds two violations: raw `<input>` and `value as any`.
  - Main runs every wired `PostToolUse` `Edit|Write` hook from `.claude/settings.json` sequentially.
  - Branch runs the wired `PostToolBatch` dispatcher once.
  - Five runs per scenario; table uses median.
- Context tax: bytes of `name + description` for skills listed in `.claude-plugin/plugin.json` that lack `disable-model-invocation: true`, plus `CLAUDE.md` bytes.
- Per-prompt injection: ran `intent-detect.sh` with `implement a new feature and open a PR`; counted emitted `additionalContext` bytes.
- Eval depth: ran `bash evals/run.sh` per tree with a 600-second cap.

Time-to-feature and code quality are not measured here. No proxy was invented.

## Findings

- The branch materially improves per-edit hook latency: -80.4% for one edit and -82.6% for four edits.
- Prompt/context load dropped: session-start tax -25.6%, model-invoked metadata -38.9%, intent injection -94.4%.
- Wired hook surface dropped far more than raw hook file count. Raw `*.sh` files only dropped -6.4% because the branch keeps shared check libraries under `.claude/hooks/checks/*.lib.sh`.
- Main evals do not produce footer totals: the suite exits early at `[cache-telemetry]`. A separate main rerun counted 332 `PASS` lines and 0 `FAIL` lines before the shell abort. The branch reaches the footer but has one failing eval: `live docs still route to removed legacy skills`.
